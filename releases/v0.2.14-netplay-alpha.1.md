An alpha of **online play** for two to four players, built on v0.2.14. It is a test build from the `netplay` branch of this fork, not a release of the main project: expect rough edges, and please report what goes wrong. Like every release it contains no game data: each player needs their own ROM of the USA release (a big-endian `.z64` of 32 MiB, SHA-1 `1159bd56730094bfc71be30113e1cfc8bacf34f3`).

> **Made with AI.** Almost all of the code was written by AI agents (Claude), directed and play-tested by a person.

**Linux (x86-64):** extract `MarioPartyRecompiled-v0.2.14-netplay-alpha.1-linux-x64.tar.gz` (glibc 2.35 or newer, a Vulkan driver, GTK 3 and FreeType; it brings its own SDL2).

**Playing online:** `ONLINE.txt` in the archive says how. In short, one player runs `host.sh` and the others `join.sh` with the host's address; the host's UDP port 7845 must be reachable from the others (forward it on the router, or share a Tailscale or ZeroTier network). Everyone needs this same build, the same mods and the same Board Movement and Map Scrolling settings; the game checks before it starts and says what differs.

**How it works:** every copy runs the whole game on the same inputs (delay-based lockstep), so each player's buttons arrive three frames (0.1 s) after they're pressed. Everyone plays from the host's save; a guest's own save isn't touched. Each frame, the copies compare a hash of the game's state, and if they ever differ the session stops and names the frame.

**Tested:** sessions of two and three players on one computer, up to 12,000 frames with 10% of packets dropped, every frame matching. **Not tested yet:** play between two different computers over the internet, and Windows.

**Missing:** a menu for hosting and joining (the scripts set it up), finding each other without forwarding a port, and rejoining a session that ended.

Reports are welcome on the [issues page](https://github.com/emmabyte/mario-party-recomp/issues), with the message the game showed when it ended.
