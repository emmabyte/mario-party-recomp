A fix for the desktop build's picture, with an update of the renderer and runtime every recomp of this project shares. Like v0.2.14 it contains no game data: you need your own ROM of the USA release (a big-endian `.z64` of 32 MiB, SHA-1 `1159bd56730094bfc71be30113e1cfc8bacf34f3`). Other regions are not supported.

> **Made with AI.** Almost all of the code was written by AI agents (Claude), directed and play-tested by a person.

**Windows:** unzip `MarioPartyRecompiled-v0.2.15-windows-x64.zip` and run `MarioPartyRecompiled.exe` from that folder (it needs a recent Visual C++ 2015-2022 redistributable, x64). **Linux (x86-64):** extract `MarioPartyRecompiled-v0.2.15-linux-x64.tar.gz` and run `MarioPartyRecompiled` in that folder (glibc 2.35 or newer, a Vulkan driver, GTK 3 and FreeType; it brings its own SDL2). Pick your ROM with **Load ROM**, then **Start Game**: the ROM is stored, so the next start goes straight to the game.

**Fixed:**

- The white glove that points at a choice in Mushroom Village's houses (the Mini-Game House, the Mushroom Shop, the Option House) slides smoothly at your display's rate. It moved in steps of 30 a second, against a room turning at the display's rate, so it looked like it shook. Other 2D pictures the game moves are drawn between its frames the same way, as the browser version already draws them.
- On Windows, a desktop build whose Direct3D 12 device is lost starts again on a new one instead of crashing.

These come with N64Recomp-browser v0.269.0's renderer and runtime. The pad mappings come from SDL's newest controller database, which adds 32 pads.

**Not checked yet:** long play sessions and rumble on a physical pad (it was played in the browser with stand-in pads). Reports are welcome on the [issues page](https://github.com/n64hub/mario-party-recomp/issues).

The [README](https://github.com/n64hub/mario-party-recomp#readme) has what works and how to build it yourself. The same game also plays in a browser, with your ROM, at [n64hub.com](https://n64hub.com/#mario-party).
